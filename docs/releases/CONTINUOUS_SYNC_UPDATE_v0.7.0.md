# Telegram Search Native v0.7.0：持续历史同步修复

## 为什么会在约 499 条停止

你截图中的“扫描 499 条、新增 39 条文本索引”说明分页已经取到多页，但旧版本把保护重复页的逻辑当成结束条件。因此只要某页重叠或游标未按预期推进，程序就会在仍有可访问历史时自行停止。反复点击只会重新开始一轮去重同步，因而可能只多出少数后来可访问的消息，或完全没有变化。

官方 TDLib 的连续请求方式是：第一页用 `from_message_id = 0`；随后将上一页最早收到消息的 ID 用作下一次 `from_message_id`。TDLib 可能返回少于指定上限的消息，并且通常会有一条重叠消息，因此应用应自行去重并继续请求，而不应把短页或重叠页视为历史结束。[1] [2]

## v0.7.0 的行为

| 事件 | 新版处理 |
|---|---|
| 收到新一页且游标向旧消息推进 | 自动继续下一页。 |
| 收到与上一页重叠的消息 | 通过 `chatId + messageId` 去重，并在后台等待后继续请求；不会自行结束。 |
| Telegram 返回空消息页 | 认定到达该会话当前可访问的历史末尾，自动切换下一个已选会话。 |
| 用户点击“完成当前页后取消同步” | 当前页完成索引后停止；这是唯一的人工停止入口。 |
| 已存在的本机消息 | 不重复写入；因此“新增”可以为 0，但“已扫描”和“第 N 页”仍会继续变化。 |

同步页现在显示当前会话、第几页、已扫描条数和新增文本索引。只要第 N 页或已扫描数在变化，应用仍在运行，不需要再次点击同步按钮。

## 使用方法

请直接覆盖安装 `TelegramSearchNative-v0.7.0-continuous-sync-debug.apk`，不要卸载旧版。进入同步页，确认已选频道后只点击一次“同步已选会话的全部历史”。让页面保持前台、网络保持稳定；需要停止时点击“完成当前页后取消同步”。如果 Telegram 最终返回空页，应用会明确显示“已到达 Telegram 返回的可访问历史末尾”。

> 该版本会持续请求，不会因扫描到 499、500 或某个固定数量而自行结束。实际可获取的历史仍由 Telegram 服务端、频道历史可见性和账号权限决定。
