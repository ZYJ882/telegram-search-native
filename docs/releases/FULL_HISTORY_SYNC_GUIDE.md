# Telegram Search Native v0.3.0：频道完整历史同步说明

## 为什么旧版只显示十几条

旧版原型对每个已选会话仅请求最近 100 条历史记录，并且只把 **纯文本消息**写入本地搜索库。因此，一个虽然有上千条动态的频道，若最近 100 条中大部分是图片、视频、贴纸、转发附件、投票或服务消息，最终可搜索的文本条目可能只有十几条。

## 新版的变化

v0.3.0 将同步升级为顺序分页模式。它会对你在“同步”页勾选的频道或聊天：从最新消息开始，每页请求最多 100 条，持续向更早的消息推进，直到 Telegram/TDLib 没有返回更早历史或达到当前可访问的历史范围。每页的文本会立即写入设备私有 SQLite 搜索索引；同一消息在跨页边界出现时会被唯一键去重。

| 新能力 | 作用 |
|---|---|
| 全量历史分页 | 不再固定只取最近 100 条；会逐页向更早历史继续拉取。 |
| 可见进度 | 显示当前会话、已扫描消息数、Telegram 返回的近似总数和已新增的文本索引数。 |
| 安全取消 | 可以点“完成当前页后取消同步”，避免数据库写入中断。 |
| 无重复索引 | 以 `chat_id + remote_id` 去重，重复同步不会生成重复搜索结果。 |
| 多会话队列 | 同时勾选多个频道时，会按顺序逐个同步。 |

## 使用步骤

1. 安装 `TelegramSearchNative-v0.3.0-full-history-debug.apk` 覆盖旧版。不要卸载旧版，这样通常会保留你在本机保存的 API 参数、会话与现有索引。
2. 打开 App 的 **同步** 页面，勾选需要同步的频道。
3. 点击 **同步所选会话全部历史**。
4. 保持 App 在前台并保持网络稳定，直至状态显示“同步完成”。大量频道可能需要较长时间。
5. 打开 **搜索** 页面，通过关键词检索设备本地已索引的文本。

## 仍可能与频道总条数不同的原因

“频道总消息数”和“搜索索引条数”不一定相同。这一版本仍然只建立可检索的文本消息索引；以下内容不写入搜索库：图片/视频等纯媒体消息、贴纸、服务消息、没有文字的转发内容，以及 Telegram 当前账号或当前会话无法访问的历史内容。TDLib 返回的 `total_count` 是**近似总数**，因此进度中的“约 N 条”用于参考，而不是精确承诺。

> 频道有上千条“信息”时，最终文本索引少于总条数并不代表消息被删除；它表示其中一部分不是可建立文本索引的内容，或当前账号无权读取。

## 使用边界

请一次同步少量频道，避免在同步过程中频繁切换网络、反复登录或强制关闭 App。验证码、两步验证密码、`api_hash` 和应用私有数据目录都不应分享。
