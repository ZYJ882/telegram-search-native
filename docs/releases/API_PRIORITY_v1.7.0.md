# Telegram Search Native v1.7.0：API 优先级与错误反馈

v1.7.0 完善 Telegram API 的选择顺序与连接失败反馈，使源码构建版本和带默认 API 的发行版本都能清楚说明当前使用的配置来源。

## API 选择顺序

| 优先级 | 参数来源 | 使用条件 |
|---|---|---|
| 1 | 设备内自定义 API | 用户已在设置页保存 API ID 与 API Hash 时始终优先使用。 |
| 2 | 构建默认 API | 仅在设备内没有自定义 API 时使用构建者通过 `TG_DEFAULT_API_ID` 与 `TG_DEFAULT_API_HASH` 注入的参数。 |
| 3 | 未配置 | 两类参数都不存在时，连接页提示前往设置填写自己的 API。 |

## 本次更新

| 项目 | 说明 |
|---|---|
| API 来源显示 | 设置页直接提示当前连接会使用设备内自定义 API、构建默认 API，或尚未配置 API。 |
| 自定义 API 优先 | 保存自定义 API 后，后续初始化 TDLib 始终先使用该参数。 |
| 无效参数反馈 | Telegram 拒绝 API ID 或 API Hash 时，连接页明确显示失败来源与 Telegram 返回的错误信息。 |
| 默认 API 处理 | 构建默认 API 失败时，提示联系 APK 构建者更新默认参数，或自行填写 API。 |
| 恢复默认 API | 已保存自定义 API 且当前 APK 含默认 API 时，可在设置页确认清除自定义参数并恢复默认配置。 |
| 数据保护 | 清除自定义 API 仅删除该设备加密保存的 API ID / Hash，不删除本地搜索索引、收藏或 Telegram 登录数据。 |

## 设计原则

用户自定义 API 被拒绝时，应用不会静默自动切换到构建默认 API。这样可以让用户明确发现失效或填写错误的配置，避免不知情地使用另一套应用参数。需要切换时，应由用户在设置页明确确认“清除自定义 API，恢复构建默认 API”。

本版本可以直接覆盖安装旧版，保留现有本机索引、收藏和登录状态。
