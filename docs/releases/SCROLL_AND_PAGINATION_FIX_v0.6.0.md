# Telegram Search Native v0.6.0：长消息滚动与历史分页稳定性修复

## 本次修复

截图中的长消息详情被放在不可滚动的容器中，超出屏幕底部的正文与操作按钮会被裁切。因此新版将整个详情页面改为独立的垂直滚动区域；现在可从正文任意位置上下滑动，查看完整文本、复制按钮和消息操作按钮。

同步停在“已扫描 1 条”是上一版分页游标的错误使用造成的。TDLib 在 `from_message_id` 非零且 `offset = 0` 时，会从该游标消息本身开始返回；把上一页最早消息原样作为下一页游标，可能反复得到同一条消息。新版会在后续页使用 `offset = -1`，保留安全重叠同时继续请求游标之前的历史；每页按消息 ID 去重，若连续重复页无法再取得更早的消息，最多重试三次后停止并给出明确诊断。[1]

| 问题 | v0.6.0 行为 |
|---|---|
| 长消息内容显示不全 | 详情页整体可上下滚动；正文、复制、收藏和跳转操作不会被裁切。 |
| 上滑没有反应 | 详情页的整屏手势会由垂直滚动容器处理。 |
| 同步只扫描 1 条就完成 | 后续请求以 `offset = -1` 从游标前继续，并按消息 ID 判断实际新增扫描量。 |
| 短页导致过早结束 | TDLib 可返回少于 100 条的页面；新版不再将短页视为结束依据。 |
| 重复页无限循环 | 连续三页都没有更早消息时停止该会话，并在同步说明中标出原因。 |

## 升级与验证

直接覆盖安装 `TelegramSearchNative-v0.6.0-scroll-pagination-fix-debug.apk`，不要卸载旧版。打开任意长消息后上下滑动，确认正文可以完整浏览。然后到“同步”页选择一个频道，仅点击一次全量同步。正常情况下“已扫描”会逐页增加；若 Telegram 仅向该第三方会话开放一部分历史，页面会显示“已到达可访问历史末尾”或“未再返回更早的可访问消息”，而不会无提示地固定在 1 条。

> 本机已存在的消息会被去重，因此“新增文本索引”可以是 0；这不代表同步没有继续。判断分页是否前进应看“已扫描”数量和同步状态文字。
